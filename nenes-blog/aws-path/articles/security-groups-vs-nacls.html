Security groups vs network ACLs

Both filter traffic in a VPC, but they sit in different places and behave differently. Knowing which is which answers many exam questions.

Two layers of defense

A security group protects individual resources such as an EC2 instance. A network ACL (NACL) protects a whole subnet. Traffic usually passes through both.

Side by side

Security groupNetwork ACL
Applies toNetwork interface / instanceSubnet
StateStatefulStateless
Rule typesAllow onlyAllow and deny
EvaluationAll rules togetherIn number order, first match wins
DefaultDeny inbound, allow outboundDefault NACL allows all

Stateful vs stateless

Because a security group is stateful, if you allow a request in, the reply is allowed out automatically. A NACL is stateless, so you must allow the reply traffic explicitly, including the ephemeral port range (1024–65535) for return traffic.

Example: a web server

  • Security group: allow inbound TCP 443 from anywhere, and TCP 22 only from your own IP.
  • NACL: allow inbound 443 and outbound ephemeral ports. Add a deny rule to block one abusive address, which a security group cannot do.

Rule of thumb

Do most of your filtering with security groups. Use NACLs as a coarse extra layer, or when you need to explicitly deny an address range.

Check your understanding
  1. Which one can contain a deny rule?
  2. Why does a NACL need rules for return traffic?
  3. At what level does each one apply?

Answer them in your own words, then compare with the linked AWS documentation.
